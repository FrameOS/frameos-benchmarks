# 2026.11.14

A full bench of the signed 2026.11.14 release images on every board of the dev box rig, on 2026-11-22. It is compared with the 2026.11.13 release (run `20261120-062810`) and with the candidate it was cut after, main `ff6a5b9d5` ([2026.11.14-rc.md](2026.11.14-rc.md)).

- **Run:** `20261122-033058`, `bench.py run --rediscover --full --baseline 20261120-062810`, about two and a half hours, every board in one run.
- **Boards:** SenseCAP Indicator D1, reTerminal E1002, E1003, E1004 and Sticky on the release's `esp32-s3-generic` / `esp32-s3-32mb` app images (downloaded from the GitHub release, flashed to ota_0). The bench records them as `2026.11.14` by their ELF sha (`bench.py sizes --elf v2026.11.14`). The Inky Frame 7.3 Spectra (Pico 2 W) is a thin client and stayed on `2026.11.12-main.e0a754bd0`: `embedded/pico` hasn't changed since.
- **Backend:** the self-hosted backend at `v2026.11.14` (`10c03217a`), with the release's `frameos-2026.11.14-wasm.tar.gz` rendering the Pico's scenes.
- **Suites:** status, reboot, benchmark, scenes, builtin, input, desktop, code, storm, soak and offline on every ESP32; status and thin on the Pico. Nothing sampled.
- **Verdict:** **0 crash, 0 fail**, 18 slow, 18 note. 2026.11.13 had 0 crash, 4 fail, 29 slow, 28 note.

## Better

- **No crash and no fail on any board, in a full run**, the same as the candidate.
- **FrameOS score up on every board:** E1002 +24 %, E1003 +41 %, E1004 +22 %, Sticky +16 %, SenseCAP +2 % (+20 % without the mismeasured 2026.11.13 switcher).
- **CPU +23 to +28 %**, nearly all of it the JSON loop (FrameOS#924's 32 KB instruction cache, as on the candidate):

  | board | 2026.11.13 JSON | candidate | 2026.11.14 |
  |---|---:|---:|---:|
  | SenseCAP | 1,343 ms | 599 ms | 635 ms |
  | E1002 | 1,267 ms | 475 ms | 520 ms |
  | E1003 | 886 ms | 462 ms | 479 ms |
  | E1004 | 1,241 ms | 478 ms | 513 ms |
  | Sticky | 890 ms | 457 ms | 481 ms |

- **Graphics:** E1003 2584 → 7135 (UI net render 73 → 10 ms: its glyph cache, FrameOS#923, and the damage repaint back); E1002 718 → 1211 (raster 3,382 → 2,204 ms and UI 335 → 181 ms; the E1002's canvas fix landed after the candidate); SenseCAP 781 → 1117; Sticky 1247 → 1625; E1004 606 → 758.
- **Image on the Spectras:** E1004 829 → 1086, E1002 1032 → 1268. The dither+pack is 4,083 → 2,545 ms on the E1004 and 804 → 507 ms on the E1002 (FrameOS#954). The E1004's scene table shows the same: `pack ~2,570 ms` on every scene, down from ~4,100.
- **SenseCAP animation:** the benchmark's animation 3.6 → 5.3 fps; the DVD logo 27.5 fps (target 30), Color cycling 20 fps (target 20).
- **Image size:** the S3 app images are **23.5 KB smaller** (3,200,752 → 3,176,720 bytes for `esp32-s3-generic`/`32mb`). The C3 images grew 2 KB (1,380,480 → 1,382,560).

## Worse

### Internal RAM: the floor kept falling after the candidate

The lowest internal RAM free since boot, after the benchmark (one reading a run):

| board | 2026.11.13 | candidate `ff6a5b9d5` | main `2032552e5` | 2026.11.14 |
|---|---:|---:|---:|---:|
| E1002 | 23.1 KB | 17.1 KB | 12.6 KB | **8.0 KB** |
| Sticky | 30.1 KB | 20.2 KB | – | 19.0 KB |
| E1003 | 42.4 KB | 32.5 KB | 32.2 KB | 32.1 KB |
| E1004 | 38.5 KB | 26.8 KB | 22.3 KB | 22.3 KB |
| SenseCAP | 13.7 KB | 13.9 KB | 13.0 KB | 11.3 KB |

Idle internal free fell by 9–14 KB on every board against 2026.11.13 (E1002 75.8 → 62.4 KB, SenseCAP 55.9 → 46.8 KB, E1004 98.1 → 84.6 KB). The first ~6 KB is FrameOS#924's trade (16 KB of SRAM for the 32 KB instruction cache, partly paid back by static Wi-Fi RX buffers). The rest came between the candidate and the release, and the E1002 has lost most: **8 KB at its lowest** is the least of any board. Nothing ran short in this run (no failed allocation, no Wi-Fi or TLS error, the SenseCAP's HTTPS server skipped for low memory as on every build since 2026.11.10), but the E1002 is now the board to watch. The two colour Spectras (E1002, E1004) lost the most after the candidate, and the firmware changes in `ff6a5b9d5..10c03217a` that touch them are the place to start: #952 (every colour e-paper draws in an RGB565 canvas), #954 (the dither and pack on both cores), #963 (pack in the canvas only where memory needs it), #966 (the palette pack's wait), plus #891 (the bigger scene store) and #962 for every board. Not bisected; one heapinfo reading a run is also a single sample.

### JSON 4–8 % slower than the candidate

On every board, the same direction (table above). Still 2–2.6× faster than 2026.11.13. Not investigated; code placement in the instruction cache moved this loop by ±10 % before (2026.11.13), and #959's −47 KB moved a lot of code.

### One flagged regression, not reproduced

- **SenseCAP Tap counter:** "fastest warm render 266 → 479 ms". The comparison took a single warm render, which the bench caught already in flight (wall 0 ms, a full draw). The switch to the scene took 1,002 ms (1,103 on 2026.11.13), and its tap answered in 1,002 ms. Not a regression on this evidence.

## Unchanged, still worth knowing

- **The E1004's 35–37 s photo and clock scenes** are mostly the 13.3" Spectra's own refresh (~25 s). Its Code editor opens in 23–35 s for the same reason.
- **E1004 interpreter discards:** 65 in the soak and 4 a scene for the photo scenes, all `low memory` with 0.9–1.7 MB free (its 1200×1600 canvas). None held a UI's tap handlers.
- **Sticky Code editor list:** opens in 8.7 s for a 1.4 s render (a code_open_wait); the scenes it opens on take 1.8–1.9 s.
- **SenseCAP animations** below target: Slideshow with motion 11.9 of 24 fps, Pixel toys 34.1 of 50, Kitchen sink 2.0 of 10, as on the candidate.

## How to repeat

```
gh release download v2026.11.14 -p 'frameos-2026.11.14-esp32-*' -p 'frameos-2026.11.14-wasm.tar.gz'
# flash each board's app image to ota_0 (~/.frameos-bench/firmware/flash_checked.sh), backend at the tag, the release wasm
tools/frame-bench/bench.py sizes --elf v2026.11.14
tools/frame-bench/bench.py run --rediscover --full --baseline ~/.frameos-bench/20261120-062810
```
